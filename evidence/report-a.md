## 2. 漂移诊断：为什么 batch1→batch2 会崩掉一整类

### 2.1 质心距离（父检查点的归一化空间）

| 类 | 同气体 batch1→batch2 质心距离 | 最近的**异类** batch1 质心 | 判定 |
|---|---|---|---|
| Ethanol | 8.85 | 9.75（Acetaldehyde） | ok |
| Ethylene | 7.47 | 11.24（Ammonia） | ok |
| Ammonia | 5.23 | 7.08（Ethanol） | ok |
| Acetaldehyde | 9.90 | 7.50（Ethanol） | **自身更远 → 必然混类** |
| Acetone | 7.65 | 8.88（Ethanol） | ok |
| Toluene | 3.45 | 7.09（Ethanol） | ok |

这是「分类边界跨 batch 不可迁移」的定量证据，而且比整体平移更糟：batch2 的 Acetaldehyde 整体落进了 batch1 Ethanol 的区域。因此任何用 batch1 标签训练出的分类器都**不可能**在 batch2 上召回 Acetaldehyde。这也说明 **macro-F1 的天花板由小类决定**，不是靠把多数类刷得更准就能提高的。

### 2.2 Acetaldehyde 是否可排序（加类别偏置能不能救）

- true Acetaldehyde n = 109，`p(Acetaldehyde)` 均值 **0.0201**、最大 0.1377；`p(Ethanol)` 均值 0.9360
- `p(Acetaldehyde)` 在 6 类中的排名分布：[0, 78, 30, 1, 0, 0]（0 = 排名第一，共 **0 例**；78 例排第二、30 例排第三）
- 全类 logit 偏置网格搜索（oracle，直接用 val 标签）：最优只到 macro-F1 **0.7276**（+0.0136），代价是 Ethanol precision 崩掉
- 嵌套检验（一半 val 调偏置、另一半评）：平均增益 **−0.0040**，即偏置调优不可迁移

### 2.3 无监督分布对齐也无效（反向证据）

| 对齐方式 | macro-F1 | Ethanol recall | Acetaldehyde recall | 说明 |
|---|---|---|---|---|
| 父模型 | 0.7140 | 0.963 | 0.000 | 基准 |
| 用 val（无标签）输入重拟合 mean/scale | 0.5221 | — | 0.000 | **不合规**（TRAINING_GUIDE 明令禁止），仅作 headroom |
| 一阶 CORAL（均值 + 协方差白化到 batch1） | 0.3104 | 0.00 | 0.000 | 更差 |
| 仅平移批均值（一阶对齐） | 0.6153 | 0.91 | 0.000 | 更差 |

> 结论：漂移不是整体平移或整体缩放这种低阶变换，无法用无监督对齐修掉。**唯一的出路是新 batch 自己的标注数据** —— 这与正式成绩单里 A 的公开验证 macro-F1 从第 1 轮 0.7257 升到第 10 轮 0.9739 完全一致（那是阶段切换后 public train 变成了新 batch 的数据，不是靠跨 batch 迁移）。所以本策略的价值不在于「修好 batch1→batch2」，而在于「新 batch 数据一到位就一次性适配好，并在没适配好时不动」。

**组分消融结论**（ep300、σ=0.8 这一列）：

- 只加噪声 → OOS +0.0025（P = 0.57），几乎无用；只加 invfreq → +0.0258 但末 epoch 崩到 0.6307（不稳）；噪声 + invfreq → +0.0273（P = 1.00）；再加通道 dropout → 末 epoch 从 0.7240 提到 0.7475。
- **噪声与 invfreq 必须成对**：噪声单独不足以改变类先验，invfreq 单独会让模型在 batch1 上过冲。
- lr = 1e-2、余弦退火、SWA（权重平均）都是 0 或负增益；batch_size 32/64/256 无差别；在 batch1 内做近因加权（α = 0.5~4）也没有增益（因为 batch1 内没有真实的时间漂移，见 §7.1）。标签平滑 0.05 是唯一略正的附加项（OOS +0.0298 vs 不加的 +0.0273），但在噪声内，不纳入推荐配方。
- 多种子（4 个 epoch 打乱种子）：σ0.8 + inv + drop ep300 末 epoch **0.7348 ± 0.0194**；plain ep60 **0.6614 ± 0.0095** —— 增益不是单次运气。


## 6. 结构性选项：hidden 32→128 的零填充拓宽（合法、可做，但不值得做）

### 6.1 迁移合法性与函数保持性（数值验证）

| 迁移方式 | 预测概率最大绝对差（256 例） | 参数量 | 拓宽后可训练？ | 说明 |
|---|---|---|---|---|
| `zero_frozen`（w1 新列 = 0，w2 新行 = 0） | **0.000e+00** | 17286 | 否（新单元梯度恒 0） | 严格 no-op |
| `small_init`（w2 新行 = 0，w1 新列 ~ N(0,(0.05/√d)²)） | **0.000e+00** | 17286 | 是（h_new ≠ 0 使 w2_new 首步就有梯度） | 推荐做法 |
| `copy_noise`（复制 4 份 + w2 行 ÷4 + 1e-3 相对噪声） | 3.732e-05 | 17286 | 是 | 近似保持 |

参数量 128·128 + 128 + 128·6 + 6 = **17286 < 100000**，`hidden = 128` 也在 `validate()` 的 [1,128] 内，所以拓宽后仍能通过 `Model.load()`。这是 CONTEXT §3 明确允许的「显式兼容的权重迁移」：w2 新行恒 0 ⇒ 拓宽瞬间 f_new(x) ≡ f_old(x)，是同一模型换更宽的参数化，不是新模型冒充续训。`strategy.py` 里实现了 `widen()` 与自检函数 `widen_prediction_error()`。

### 6.2 但它没有稳定增益，而且表面增益是伪造的

| 实验 | macro_f1 | 结论 |
|---|---|---|
| ep60 lr3e-3 原宽度（不拓宽） | 0.7264 | 基准 |
| ep60 lr3e-3 zero_frozen 128 | 0.7271 | 与基准差在噪声内 |
| ep60 lr3e-3 small_init 128 | 0.7274 | 同上 |
| ep60 lr3e-3 copy_noise 128 | 0.7288 | 同上 |
| **不拓宽、只把 Adam 一/二阶矩清零（60 ep）** | **0.7274** | 几乎解释了全部「拓宽收益」 |
| σ0.8 + inv + drop ep300 + widen128 | 0.7490（OOS +0.0178，P = 0.90） | 比不加 widen 的 0.7553（OOS +0.0273）**更差** |
| 多种子 best-epoch：widen_copy vs plain | 0.7255 vs 0.7262 | 无差别 |

**决定性隔离实验**：把 Adam 状态也一起重置后，`zero_frozen` 拓宽 128 与原宽度各训 10 epoch 的 macro-F1 **完全相同（差 0.000e+00）**，换 3 个种子也逐位相同。这证明：纯零填充拓宽在训练轨迹上是恒等变换，它的全部「收益」来自 `widen()` 顺手把 Adam 一/二阶矩清零（一次合法性内的优化器状态重置）。`small_init` 打破了对称性（新单元确实在学），但收益依旧不如纯正则化。

**建议**：默认关闭；只在 `len(train) ≥ 1500`（容量才有意义）时作为额外候选参战。本包 445 行时它总是输给正则化候选。


## 7. 稳健性

### 7.1 批次留一（batch LOO）与「为什么不能做 batch 内时间切分」

本包只有两个批次：train = batch1（445 行）、validation = batch2（1244 行）。所以「留一批次」只有 **batch1 → batch2** 这一个方向，也就是上面所有表的口径；反方向（batch2 训练 → batch1 验证）不可做，因为那会把验证标签并入梯度（合规红线 §5.2）。

原计划的「batch 内时间切分」经诊断**不可用**：batch1 按 `source_index` 排序后只有 8 次类别切换，块结构为

```
Ethanol×84 · Ethylene×88 · Ammonia×76 · Ethanol×6 · Ethylene×10 · Ammonia×7 · Acetaldehyde×30 · Acetone×70 · Toluene×74
```
即同一气体的样本是**连续成块**排列的。任何「前 60% 训练 / 后 40% 验证」的时间切分都会造成**训练与验证类别不相交**（我试做伪阶段时得到 train 只有 Acetaldehyde/Acetone、val 只有 Acetone/Toluene，父模型 macro-F1 = 0.0），构造完全无效。**这条对 B/C 题同样重要**：`source_index` 不是可用时间轴。

替代做法：分层抽样造「小 train」，eval 固定在完整 batch2 上，衡量「本轮 public train 只有 k 行时该不该训」。

| 公开 train 行数 k | 拟合方式 | Δ macro_f1 中位数 | 均值 | 最差 | 最好 | P(Δ>0) |
|---|---|---|---|---|---|---|
| 44 | plain | -0.0489 | -0.0574 | -0.2218 | +0.0126 | 0.25 |
| 44 | recipe | -0.0343 | -0.0509 | -0.1651 | +0.0167 | 0.25 |
| 90 | plain | -0.0247 | -0.0424 | -0.1248 | +0.0055 | 0.12 |
| 90 | recipe | -0.0529 | -0.0468 | -0.0894 | +0.0080 | 0.12 |
| 180 | plain | -0.0061 | -0.0118 | -0.0549 | +0.0103 | 0.50 |
| 180 | recipe | -0.0036 | -0.0041 | -0.0267 | +0.0174 | 0.38 |
| 281 | plain | -0.0032 | -0.0369 | -0.1666 | +0.0064 | 0.50 |
| 281 | recipe | -0.0093 | -0.0034 | -0.0226 | +0.0299 | 0.38 |
| 445 | plain | -0.0892 | -0.0892 | -0.1215 | -0.0569 | 0.00 |
| 445 | recipe | +0.0169 | +0.0169 | +0.0167 | +0.0171 | 1.00 |

**读法**：k ≤ 281 时几乎任何训练都在**伤害** batch2（因为抽到的仍是 batch1 的样本，只是信息更少）；只有 k = 445（信息最全）时正则化配方才稳定为正（+0.017，P = 1.00）。这说明「训练是否有利」取决于新数据是否带来**新的分布信息**，而不取决于训练量 —— 正是策略必须每轮用 validation 自查、且不显著就保留父模型的原因。

### 7.2 置信区间（bootstrap，2000 次）与「小类必须标注」

- 父模型 macro-F1 = 0.7140，绝对 95% CI **[0.6485, 0.7557]**（sd 0.0271）。**任何 < 0.03 的单点差异都不能靠这个区间判真伪**，必须用配对 bootstrap。
- 推荐候选 vs 父：配对 bootstrap 差 **+0.0413，CI95 [+0.0187, +0.0732]，P(diff>0) = 1.00**（配对比较消掉共享的样本噪声，区间比绝对值区间窄得多）。
- **Toluene 只有 5 例**：它的 F1 只能落在少数格点上，单例翻转就能让 macro-F1 跳 ±0.028~0.056。所有「Toluene F1 从 0.667 涨到 0.769」的叙述都应视为**4 个样本的搬运**，不是稳定能力。
- Acetaldehyde 的 0.000 → 0.053 同样只是 3 个样本被救回（109 中的 3 个），不改变「该类不可学」的判断。

### 7.3 候选相对父模型的位移（正则化强度的直接证据）

| 候选 | 参数相对父的 L2 位移 | val macro_f1 |
|---|---|---|
| fit-now-plain | 0.455 | 0.647411（ep75） |
| regularized-lite | 0.939 | 0.750135（ep300） |
| regularized-strong | 0.968 | 0.755890（ep300） |

三个候选的位移量级（0.45 / 0.94 / 0.97）在同一量级上，差别不在「挪了多远」而在「挪的方向是否被噪声平滑」。plain 候选位移最小却最差（0.6474），说明**位移小 ≠ 安全**；真正的保护来自噪声对 batch1 特有方向的抑制。


## 9. 推荐配置、预期增益与风险



### 9.1 推荐配置（已落在 `strategy.py` 默认值）

```
候选池   : fit-now-plain / σ0.5+invfreq+drop0.1 / σ0.8+invfreq+drop0.1
lr       : 沿用父检查点（0.003），clip 到 [1e-3, 5e-3]
epochs   : 约 1200 梯度步/候选（445 行 ≈ 300 epoch；行数变多自动减少 epoch，算力恒定）
batch    : 沿用父检查点（128）
快照点   : epoch 的 25/50/75/100%
归一化   : 沿用父检查点，**不重拟合**（重拟合实测 −0.19，即使再训也只回到 0.7355）
接受条件 : gain ≥ 0.008 且 配对 bootstrap P(diff>0) ≥ 0.80
拒绝时   : 返回父检查点（selected="parent"），不做「为了提交而提交」
耗时     : 2.3 s（budget 150）/ 1.1 s（budget 40）；按 8× 慢机器估算仍 < 20 s
```

### 9.2 预期隐藏测试增益（诚实区间）

| 口径 | 数值 | 说明 |
|---|---|---|
| validation 实测（本包 batch2） | **+0.0419**（0.7140 → 0.7559） | 含快照点 + 候选池的 val 选型，偏乐观 |
| 固定配方、无 epoch 选型 | +0.0335（0.7475） | 配方先验确定后 val 只做测量，偏乐观程度小 |
| **样本外半分割（推荐判据）** | **+0.0273 ± 0.0195，P = 1.00** | 对「挑 epoch」过拟合免疫；配方本身仍是在同一 val 上选的 |
| 扣掉配方选择偏差后的预期 | **+0.010 ~ +0.025 macro-F1** | 我对隐藏 stream 的保守估计 |
| 单个新 stage 的最坏情况 | 约 0（门槛挡住）；无门槛时 −0.07 ~ −0.12 | 这就是必须保留 `selected="parent"` 的原因 |

### 9.3 风险

1. **小类仍然不可学**：Acetaldehyde 在 batch1 上根本不可分。若某阶段 public train 里它依然稀少（本包 30 行），隐藏 batch 上这一类仍可能 0 召回。macro-F1 对它是等权重的，**这一项上限约 +0.167**，不要期待靠调参突破。
2. **Toluene 只有 5 例是本策略最脆的点**：`invfreq` 会把 Toluene 权重抬到约 1.0（本包 74 行）；若某阶段 Toluene 只有 2–3 行，权重会到 20+ 倍，可能把模型推向乱判。已用 `max(n_c,1)` 兜底并靠 validation 门槛拦截，但建议 lead 监控这个信号，必要时对 n_c < 5 的类把权重 power 降下来。
3. **调用方必须传「平台实际采纳的检查点」**：若某轮我们返回 parent，下一轮仍应从同一个 parent 继续，否则会重复训练已经被否定的方向。
4. **不重拟合归一化的代价**：若某阶段新 batch 的整体尺度变化极大，特征在旧归一化下会偏离数个 std。我实测重拟合更差，但那条实验的前提是「父模型带着旧归一化训了 20 epoch」；若某阶段 public train 行数很大（> 2000）且类别齐全，可以再评估一次「重拟合 + 多跑 epoch」，这属于需要 lead 决策的开放项。
5. **margin 的自适应性**：0.008 是按 n_val ≈ 1244 算的。若某阶段 public validation 只有 200–300 行（配对差 sd 会涨到 0.03+），门槛会变得过松。`strategy.py` 已按 n_val < 800 自动抬到 0.020，但更稳的做法是用「样本量 → margin」表统一管理。

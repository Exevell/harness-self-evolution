## 2. 决策树（试运行 v14 的三种结果）

```
v14 试运行结果
├─ completed，且隐藏指标正常（A≈0.90 / B≈379 / C≈55.7）
│    → 1.0.5 可用，v15 直接打第 1 次正式评测（不再花试运行）
│
├─ failed: CHUNKED_UPLOAD_UNSUPPORTED / 上传相关
│    → 宿主不支持分块上传 → 回退镜像 harness-3.0.2（SDK 1.0.2 内联上传，历史 30 轮全通）
│      v15 的代码补丁保持不变，只把镜像里的 SDK 换回 1.0.2，重打镜像 → 1 次试运行验证 → 正式
│
└─ failed: 其它（artifact / 内存 / 超时）
     → 读 failure_detail 定位；优先用 harness-3.0.2（已知可用）保底，不消耗第二次正式机会
```

## 3. 正式评测后 24 小时内必须做的事

1. 拉 `report` 与 `objective_result`，把五项分项与上次（12.4576 / 14.5534 / 14.2488）并列对比；
2. 若 `resource_efficiency` 仍为 0 → 结论：该项未启用，后续不再为它做牺牲性优化；
3. 若 `mean_gain` 相对 v9 未提升 → 说明"指标不变只提速度"拿不到分，第 2 次正式必须带**真实指标提升**（届时只剩 C 比值扩张这一条路，需先试运行验证）；
4. 写下复盘：预期 vs 实际、差异原因、剩余 1 次的用法。

# 设计说明（Design Justification）

> 本文说明 HAR-02 / HAR-03 / HAR-04（镜像 4.2.0）的设计取舍与证据来源；技术细节与实验数据见技术报告（第 1 部分）。

## 1. 问题定位

赛题给的是"漂移数据流 + 固定父检查点 + 每阶段公开投影"的持续演化任务，不是一次性训练任务。
上一版（HAR-01）失败的三条根因都在代码层可查：

1. 每轮只训 1–4 个 epoch（10 轮累计约 20 epoch，父模型本身已训 15–20 epoch）；
2. C 题把 113,089 行训练集截断成有序前 12,000 行、23,049 行验证集截成 3,000 行 → 分布偏斜、模型坍缩成常数；
3. 没有"不改进就保留父模型"的机制，兜底强制训练 1 epoch 后提交，出现过候选比父模型更差仍上线（B 题 3 轮）。

因此本系统的设计目标不是"单轮刷分"，而是 **让单轮最坏情况等于"不改"**。

## 2. 总体架构：两层受控自改进（RSI）

```
每轮：
  ① 读历史（rnd.history + 上一轮 state）
  ② 评测父模型（在同一份公开 validation 上）
  ③ 候选训练（按数据集策略池，预算感知）
  ④ 大模型评审（rnd.model，回执号写入决策记录）
  ⑤ 门槛判定（阶段感知边际；不达标 → 保留父模型）
  ⑥ 提交 / 回滚 + 写 state
```

- **模型层自迭代**：每轮都从平台给的父检查点真实续训（保留 Adam 状态与归一化统计），
  不重新初始化、不改特征 schema。检查点仍是官方 `contest.cpu-mlp.v1` 格式。
- **策略层自改进**：把"用什么候选、门槛多少、什么时候回退"写成显式规则与可配置边际，
  并把每轮的真实实测写进 `finish` 的 hypothesis / change_summary / reason / configuration，
  形成可追溯的"读历史—做实验—依据结果决策"链。

## 3. 关键设计决策与备选方案

| 决策 | 采用 | 被否决的备选 | 证据 |
|---|---|---|---|
| 是否每轮都提交候选 | **不**：候选必须超过边际才上线 | "总是提交训练后的产物"（HAR-01 做法） | HAR-01 的 B 题 r5/r8/r10 候选优于父模型为负仍上线；A 题 6/10 轮、B/C 各 9/10 轮保留父模型后，`not_below_static_baseline` 由 false → true |
| 边际怎么取 | 基础边际 + **阶段感知**：新阶段首轮放宽、同阶段严格、小投影不放宽 | 固定边际（对所有轮次同一门槛） | 阶段切换时父模型在新投影上会掉分（A 从 0.714 到 0.702/0.812、C 从 41.98 到 42.14），固定边际会错过适配窗口 |
| 哪些数据集允许放宽 | **只 A/C**；B 永久 5% | 三题都放宽 | 第 3 次试运行实测：B 放宽到 1% 后隐藏集 RMSE 从 379.46 恶化到 707.09（+86%）——公开验证集被单根长寿命轴承主导，放宽等于放大过拟合。据此回退 |
| A 题怎么适配新批次 | 类平衡 + 高斯噪声 + 通道 dropout 的正则化候选，配对 bootstrap 门槛 | 标签移位校正（BBSE/EM）、CORAL、批均值对齐 | ORACLE 先验校正上界 0.5912 < 基线 0.7140；CORAL 0.31；批均值对齐 0.62——A 是协变量漂移，无监督对齐不可行 |
| B 题怎么处理跨轴承差异 | 回归**寿命分数** `p=y/D_b`，用单一先验还原分钟（等价于目标仿射，折进 `target_scale/mean`） | log1p/幂变换、保序校准、按工况归一化 | LOBO 显示预测水平与轴承寿命无关；log1p/幂变换需非仿射逆变换（不可部署）；保序校准把预测压成常数（IQR 15.9 vs 真值 839），已否决 |
| C 题怎么压长尾 | 全量续训 + 长寿命加权 w=1.5 + 受保护尾部仿射 + NASA 守卫 2.5× | 重拟合归一化、Huber、log1p、hidden 拓宽 | 重拟合 mean/scale 掉到 0.5221；Huber/log1p 无净收益；拓宽 128 无稳定增益 |
| 是否用 GPU / 外部模型 | **不用**：纯 NumPy、CPU、镜像内不联网 | 引入 GPU 或外部预训练权重 | 评测环境为 2 核 4 GiB；镜像只装 NumPy；隐藏测试由平台托管 |
| 资源怎么控 | **分层**：B/C 在"投影字节指纹相同 + 上一轮已判 parent"时只做 1 次模型调用后快进；**A 不快进**（每轮真实重训，`CONTEST_FASTPATH` 默认 `B,C`）；prompt 只带决策标量 | 全部快进（4.1.0 行为）或每轮全量重训 | 2c4g 口径 30 轮墙钟 **52.2 s**（A 18.0 / B 6.7 / C 22.2 s），峰值 229.4 MiB；A 不快进只多 14.5 s/10 轮，公开流上与快进**逐位同指标**——这是**预防性保险**：隐藏 A 在 4.1.0 与 3.0.0 之间无显著差异（v14 试运行 0.8828 vs v12 正式 0.8848，差 0.002），真正掉分未得到证实；B 隐藏 379.46 与快进逐位一致 |

## 4. 安全与可控性

1. **不能改坏**：门槛 + 回滚，单轮最坏情况是"不提交"；预测入口只读 `/model`，不写任何目录。
2. **不能作弊**：不读原始 CSV、不读隐藏轴承、不把验证集标签并入梯度训练；`meta` 只用于事后分组分析，
   从不进入模型输入（`data.py` 的 `FORBIDDEN_INPUTS` 也会拒绝目标派生字段）。
3. **不能失控**：预算按 `rnd.wall_seconds` 分配（≤40%，上限 180 s），分块计时早停；
   单轮内所有随机性来自 seed 与 epoch 索引，结果可复现。
4. **密钥不入镜像**：PyTRiO Key 只填平台密钥栏，镜像、源码、文档、日志里都没有。

## 5. 可复现性

- 镜像 `/app` 与源码仓库逐文件 sha256 一致（作品文档附录 A；4.2.0 实测 **13/13**，可用 `tools/build_source_zip.py --image-app` 一键复核）；
- 三题完整实验报告与 30 轮协议仿真记录随仓库提交（`evidence/`）；
- 复现命令见 `docs/run_manual.md`；关键数字都能回溯到具体脚本或平台回执。

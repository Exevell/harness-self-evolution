# 设计论证

本文回答三个问题：为什么这样分工（大模型 vs 规则 vs 闸门）、为什么这三个策略被选中、为什么闸门多次否决了"看起来更好"的分数。文中所有数值取自 `submission_runs/{A,B,C}/experiment_history.jsonl`（当前镜像实测）与各任务包 `training.json`（官方基线）。

---

## 1. 为什么是"大模型选策略 + 规则做闸门"的两层结构

### 1.1 赛题要求的两种能力

赛题要"模型层自迭代 + 策略层自改进"。这两件事的失败模式完全不同：

- **模型层失败**：续训把模型带偏（本例 C 题从基线 52.87 掉到 92.86），表现为分布崩坏。
- **策略层失败**：选了一个"分数好看但机制错误"的策略（本例 B 题 shrink 系列），表现为分布坍缩。

前者需要**度量**，后者需要**判断**。度量适合写成确定性的规则代码，判断则需要读代码、读诊断、读历史——这正好是大模型擅长的部分，也正是规则表做不好的部分。

### 1.2 三层职责划分

| 层 | 由谁做 | 具体内容 | 为什么必须是它 |
|----|--------|----------|----------------|
| 监测与诊断 | 规则（numpy） | 质心偏移、跨批次 LDA、分轴承 MSE 占比、分段 bias | 需要可复算、可审计；每轮结论必须一模一样 |
| 策略选择 | 大模型（PyTRIO Qwen3.5-4B） | 在白名单内选策略 + 调超参，给理由 | 需要综合"诊断语义 + 基线代码 + 历史"做取舍 |
| 上线与否 | 规则（三道闸门） | IQR 坍缩 / 常数等价 / 分轴承 bias | **不可交给模型**：模型会为"分数变好"而合理化 |

### 1.3 为什么不让大模型直接改代码

`llm_advisor` 的输出里有 `code_notes` 字段，模型确实会读基线 `model.py` 并指出"当前代码用 Adam、学习率 0.003、候选策略都没动它"。但它**只能**输出策略名和超参，改不了代码。原因：

1. 自改代码无法逐轮审计，与"受控 RSI"直接冲突；
2. 一旦允许改代码，闸门就只能看结果，看不到改动本身的合规性；
3. 当前策略空间（10 个策略 × 若干超参）已经覆盖了诊断能指向的所有动作。

这是**刻意的能力上限**，不是能力不足。

## 2. 为什么这三项策略

### 2.1 A 题：类平衡加权 + 高斯增强 + 余弦退火

**诊断实测值**（当前镜像 round-01）：

| 指标 | 值 | 含义 |
|------|----|------|
| 跨批次 LDA 准确率 | **0.4043** | 用 batch1 训练、batch2 测试的线性判别器 |
| 随机基线 | **0.4277** | 按类频率猜的期望准确率 |
| 最大质心偏移 | **9.90** | 归一化特征空间的类质心位移 |

LDA 准确率**低于**随机基线，是"决策边界完全不可迁移"的强证据：不是模型不够强，是同一类在两个批次里落到了不同位置。因此正确的动作是**协变量漂移应对**（重加权 + 增强），而不是标签校正。

**为什么是逆频率加权**：少数类在训练集占比低，漂移后更容易被边界吞掉；逆频率加权把损失向少数类推。

**为什么是 σ=0.5 的高斯噪声**：在归一化空间注入噪声，等价于让模型见过"同一类略微偏移"的样本，是最便宜的不变性训练。

**为什么是余弦退火到 1e-6**：避免末期学习率过大破坏已收敛的边界，同时保留 `max(lr, 1e-6)` 的下限，保证数值稳定。

**实测代价（必须承认）**：Macro-F1 从 0.7140 升到 0.7412，但分类别 F1 里第 4 类只有 **0.0531**。加权没有救回这一类——它在验证批次里几乎无法区分。宏平均被其余 5 类拉起来，所以这 +3.8% 是"不均匀的胜利"。

### 2.2 B 题：向训练集中位数收缩（及其失败）

**诊断实测值**：

| 指标 | 值 |
|------|----|
| 训练集寿命中位数 | 758.5 分钟 |
| 寿命空档 | 532 → 2495 分钟（跨度 1963） |
| 验证集分轴承 MSE 占比 | Bearing1_4 39.9% / Bearing2_4 44.5% / Bearing3_4 15.6% |
| 最大占比 vs 主导阈值 | 44.5% < 80% → 诊断输出 `unknown / none` |

值得注意：**诊断没有判定"存在主导轴承"**，因为最大 MSE 占比只有 44.5%，低于 80% 阈值。所以诊断给出的动作是 `monitor_only`，而大模型仍然在策略池里选了 shrink 系列——这是模型在"无明确诊断"时倾向于保守收缩的表现。

**策略的机制**：把预测 `p` 向训练集中位数 `c=758.5` 收缩，`p' = a·p + (1−a)·c`。收缩系数 `a` 越小，预测越靠近常数。

**这一机制必然导致的结果（被闸门抓住）**：

| 轮次 | a | 预测 IQR | IQR/真值(839) | RMSE | 判定 |
|------|---|----------|--------------|------|------|
| round-01 | 0.30 | 67.18 | **0.080** | 458.48 | IQR 坍缩 → 回滚 |
| round-02 | 0.45 | 100.77 | 0.120 | 467.64 | 与常数 470.86 等价 → 回滚 |
| round-03 | 0.60 | 134.36 | 0.160 | 486.06 | 与常数等价 → 回滚 |

收缩让 RMSE 从官方基线的 681.16 一路降到 458.48（−32.7%），但代价是**预测分布被压平**：真值 IQR 是 839，模型只给出 67。这不是学到了映射，而是把输出推向验证集分布的中心，让"平均误差"变小。

**结论**：B 题的正确方向不是全局收缩，而是对寿命空档区间（532～2495）做结构性外推。当前策略池里没有这个动作，这是设计上的缺口。

### 2.3 C 题：长寿命加权 + 长时训练（及其失败）

**诊断实测值**：

| 指标 | 值 |
|------|----|
| 长寿命区间（RUL>150）平均 bias | **−224.2** 循环（系统性低估） |
| 该区间样本占比 | 25.3% |
| 真值 IQR | 111 |
| 可部署常数 RMSE | 79.41（训练集中位数 114.0） |
| 官方基线 RMSE | 52.87 |

诊断说"长寿命区间被低估 224 循环，但样本占 25%，不算稀少"，于是动作是 `long_life_weighting`（RUL>150 的样本加权 ×3）配合 300 epoch 长训。

**实测结果与设计预期的差距（必须写明）**：

| 轮次 | 策略 | RMSE | 与常数 79.41 比 | 判定 |
|------|------|------|-----------------|------|
| round-01 | rul150x3, 300ep | 92.86 | 差 17% | 回滚（IQR 0.00046 + 常数等价） |
| round-02 | rul125x2, 300ep | 262.45 | 差 230% | 回滚 |
| round-03 | uniform, 300ep | 101.12 | 差 27% | 回滚 |

**根因**：基线自身只训了 15 epoch / 6630 step（见 C 包 `training.json` 的 `final_epochs=15`），而策略池一律续训 300 epoch。在只有 833 个参数的小网络上，300 epoch 足以把权重带离基线解，而验证集只有一份、无法做早停选轮（赛规不允许用验证集挑轮次）。结果是"训练更久→更差"。

这不是闸门的错，闸门成功阻止了上线；这是**策略池的时间尺度错配**。修法很明确：策略池必须包含 `epochs ∈ {15, 30, 60}` 这类与基线同量级的选项，且把基线 `training.json` 喂给大模型，让它知道"基线只训了 15 epoch"。

## 3. 为什么闸门要否决"更高分"

### 3.1 三个必须被否掉的场景

| 场景 | 表面分数 | 真实机制 | 哪道闸门抓住 |
|------|----------|----------|--------------|
| B 题 shrink a=0.30 | RMSE 458.48（比基线好 32.7%） | 预测 IQR 67 vs 真值 839，输出被压向中位数 | IQR 坍缩（ratio 0.080） |
| B 题 shrink a=0.45 | RMSE 467.64 | 与"训练集中位数常数"统计等价 | 常数等价（> 470.86×0.98） |
| C 题 rul150x3 | RMSE 92.86 | 预测 IQR 0.05 vs 真值 111，几乎恒定输出 | IQR 坍缩 + 常数等价 |

三个场景的共同点：**分数确实变好了，但模型没有学到更多东西**。如果只看验证集 RMSE，系统会连续三次"成功上线"，而实际交付的是一个几乎恒定的预测器——在隐藏测试集上会立刻崩。

### 3.2 为什么"可部署常数"用训练集中位数（470.86）而不是验证集中位数（465.73）

- **465.73（预言机常数）**：需要验证集标签才能算出来，属于赛规禁止的信息使用。它只能作为记录字段 `rmse_const_oracle` 存在，不能进判定。
- **470.86（可部署常数）**：只用到训练集标签中位数 758.5，在推理时完全可得，因此可以作为"零信息基线"参与判定。

判定口径：`rmse_model > rmse_const × 0.98` 视为与常数等价（留 2% 容差，避免噪声误判）。这个 0.98 是人工设定的常量，未做自适应——列在已知局限里。

### 3.3 为什么 IQR 闸门阈值是 0.1

真值 IQR 代表"这个任务本身有多大的变化范围"。如果模型输出 IQR 不到真值的 10%，它已经丢弃了九成以上的变化信息，此时任何 RMSE 优势都来自"押中中心"，不来自建模。B 题三轮分别落在 0.080 / 0.120 / 0.160，第 1 轮刚好被拦下，第 2、3 轮靠常数闸门拦下——两道闸门互为补充，说明单靠一道不够。

## 4. 为什么诊断指标选这些

| 任务 | 选用的诊断 | 能回答的问题 | 被否决的替代方案 |
|------|-----------|--------------|------------------|
| A | 质心距离 + 跨批次 LDA vs 随机 | 边界能不能迁移？是协变量漂移还是标签移位？ | KL 散度（高维估计不准）、MMD（慢） |
| B | 寿命分布空档 + 分轴承 MSE 占比 + 分轴承 bias | 误差集中在哪根轴承？那个区间训练时见过吗？ | 工况分类（推理端拿不到工况标签） |
| C | 分段 bias + 该段样本占比 | 低估发生在哪一段？那一段是不是稀少？ | 全局 RMSE（掩盖分段差异） |

共同原则：**诊断必须只用推理时可得的信息**。B 题工况分类被否掉，就是因为 `predict.py` 会剥离 meta，推理端拿不到工况标签。

## 5. 为什么记录要写到字段级

每轮 `experiment_history.jsonl` 一条记录，包含：`stage_id`、完整 `strategy`（含全部超参）、`validation_metric`、`diagnosis`（含证据与 `drift_metrics`）、`monitor_result`（轴承寿命、占比、gap）、`degradation_checks`（三道闸门逐项原始值）、`passed`、`notes`、`llm`（`source`/`reason`/`code_notes`/`usage`/`latency_s`/`attempt`）。

这样做的直接好处：**任何一次"为什么回滚"都能被第三方复算**。例如 B 题 round-01 回滚，评委只需读 `degradation_checks.iqr_collapse` 就能看到 `ratio=0.08007084509844`，而不必相信我们的叙述。

## 6. 总结

本系统的设计原则，按优先级排列：

1. **分数不重要，机制重要**：闸门否决了所有"分数更好但机制错误"的策略（B 题 3/3、C 题 3/3）。
2. **诊断只用推理时可得的信息**：可部署常数用训练集，不用验证集。
3. **判断交给模型，否决交给规则**：模型可以提议，不能决定上线。
4. **所有结论可复算**：字段级记录，任何人可复核。
5. **诚实口径**：A 题只有 +3.8% 且不均匀；B、C 题当前没有可部署改进——这些都写在技术报告里，不做修饰。

# 设计论证

## 1. 为什么选择两层自进化架构？

### 1.1 赛题要求

赛题明确要求"模型层自迭代＋策略层自改进"的两层自进化机制，这是核心评分维度（方法设计 30 分）。

### 1.2 技术合理性

**模型层自迭代**：
- 基于检查点的续训，保持架构不变
- 每轮生成 `checkpoint.npz`，可追溯父检查点
- 符合"受控 RSI"理念：改进必须可验证、可回滚

**策略层自改进**：
- 基于历史实验记录的决策规则自动更新
- 前 3 轮探索，第 4 轮起读历史决策
- 符合"≥3 次读历史—做实验—依据结果决策"要求

### 1.3 对比方案

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| 纯手动调参 | 灵活 | 不满足"无人工干预"，无法自动化 | ❌ |
| 网格搜索 | 系统 | 无法根据漂移类型调整策略 | ❌ |
| **两层自进化** | 自动化 + 可解释 + 可追溯 | 实现复杂 | ✅ |

## 2. 为什么选择这三项策略？

### 2.1 A 题：类平衡加权 + 高斯增强

**诊断依据**：
- 批次质心距离：Acetaldehyde 9.90（最大），Ethanol 8.85
- Oracle LDA 跨批次准确率 0.3663 < 随机 0.6007
- **根因**：协变量漂移，决策边界不可迁移

**策略选择逻辑**：
1. **类平衡加权**：训练集 Acetaldehyde 仅 30 样本（占比 6.7%），验证集 109 样本（占比 8.8%）。逆频率加权让模型关注少数类。
2. **高斯增强**：归一化空间 σ=0.5 的噪声模拟批次漂移，增强泛化性。
3. **余弦退火**：250ep 后学习率衰减到 1e-6，模型自然收敛，无需 SWA。

**否决的方案**：
- 标签移位校正（BBSE/EM）：连 ORACLE 都只有 0.5912 < 基线 0.7140
- 目标端归一化（TENT/CORAL）：违反赛规"不使用验证集标签拟合统计量"
- 仿射抖动：0.7516 vs 高斯 0.7522，无优势

### 2.2 B 题：向训练集中位数收缩

**诊断依据**：
- 寿命空档：训练集 532→2495 分钟，Bearing3_4（1514 分钟）正落中央
- 分轴承 MSE 占比：Bearing3_4 贡献 90.2%
- 特征信号强度：Bearing3_4 的 rms 与 RUL 秩相关仅 +0.11
- **根因**：信号本身缺失 + 跨轴承水平错位

**策略选择逻辑**：
1. **收缩**：模型预测过度压缩（bias 模式：[0,50) +231.70, [900,1600) -986.19），向中位数收缩可缓解。
2. **中位数而非均值**：训练集寿命分布右偏（均值 954.15，中位数 758.50），中位数更稳健。
3. **收缩系数 a=0.45**：LOBO macro 599.36，val RMSE 452.64，两套指标同时击败常数与基线。

**否决的方案**：
- 工况归一化：推理端拿不到工况标签（`predict.py:34` 剥离 meta）；工况分类准确率仅 8.4% < 随机 33%
- log1p 目标变换：单次划分下 RMSE 610（identity 500），LOBO 显示在 7/9 轴承上大胜但 worst-bearing 1336 > identity 1288
- 保序校准：退化成常数（IQR 15.9 vs 真值 839）

### 2.3 C 题：长寿命加权 + 长时训练

**诊断依据**：
- 分段 bias：[400,900) 区间仅 44 个样本，低估约 190 循环
- NASA 惩罚：`exp(190/13) ≈ 2.2e6` 每样本，主导了整个分数
- **根因**：长寿命样本稀少导致低估被非对称评分放大

**策略选择逻辑**：
1. **长寿命加权**：RUL > 150 的样本权重 × 3，让模型关注长寿命区间。
2. **长时训练**：300ep 是 RMSE 与 NASA 的 Pareto 最优点（50.54 / 3.448e9）。
3. **余弦退火**：学习率从 3e-3 衰减到 1e-6，稳定收敛。

**否决的方案**：
- 线性加权 `w4_linear`：NASA 爆到 7.242e10（基线 5.823e9）
- 极致长时训练 1200ep：RMSE 50.29 更优，但 NASA 反弹到 1.152e10

## 3. 为什么选择这些诊断指标？

### 3.1 A 题：批次质心距离 + Oracle LDA

**选择理由**：
- 质心距离直接量化漂移幅度
- Oracle LDA 跨批次准确率量化决策边界可迁移性
- 对比随机基线，判断是否真的不可迁移

**对比方案**：
| 指标 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| KL 散度 | 理论完备 | 高维估计不准 | ❌ |
| MMD | 非参数 | 计算慢 | ❌ |
| **质心距离 + Oracle LDA** | 直观 + 可解释 | 线性假设 | ✅ |

### 3.2 B 题：寿命空档 + 分轴承 MSE 占比

**选择理由**：
- 寿命空档直接解释"为什么模型在某些区间表现差"
- 分轴承 MSE 占比识别主导误差来源
- 特征信号强度（Spearman 相关）判断是否值得继续优化

**对比方案**：
| 指标 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| 工况分类准确率 | 检测工况差异 | 推理端拿不到工况 | ❌ |
| **寿命空档 + 分轴承 MSE** | 直接 + 可操作 | 需要轴承 ID | ✅ |

### 3.3 C 题：分段 bias + NASA 惩罚分析

**选择理由**：
- 分段 bias 定位低估区间
- NASA 惩罚分析量化每个区间的贡献
- 直接指导加权策略（哪个区间需要加权）

**对比方案**：
| 指标 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| 全局 RMSE | 简单 | 掩盖分段差异 | ❌ |
| **分段 bias + NASA 分析** | 直接指导策略 | 需要分段阈值 | ✅ |

## 4. 为什么选择 LOBO 交叉验证？

### 4.1 问题发现

单次 train/val 划分给出与 LOBO 完全相反的结论：
- B 题 log1p：单次划分 RMSE 582（identity 497），看似更差
- LOBO 显示：log1p 在 7/9 轴承上大胜（Bearing1_1: 83.89 vs 728.87）

### 4.2 根因分析

公开验证集 90.2% 由 Bearing3_4 构成，不代表隐藏测试。单次划分等价于"用一根轴承评估所有模型"，方差极大。

### 4.3 LOBO 的优势

1. **轴承级泛化估计**：每次留出一根轴承，更贴近隐藏测试
2. **按寿命分组**：识别短/中/长寿命区间的表现差异
3. **worst-bearing**：识别最差的轴承，防止"平均好但某根轴承极差"

### 4.4 LOBO 的局限

1. **pooled LOBO 被巨型轴承污染**：Bearing3_1/3_2 各 2500+ 样本，留出时剩余训练集中位数崩掉
2. **解决方案**：按寿命分组报告（short/mid/long），并同时看 macro 与 worst-bearing

## 5. 为什么选择三道退化闸门？

### 5.1 问题发现

B 题保序校准给出 RMSE 461.57（低于常数下限 465.55），看似突破。但诊断发现：
- 校准后 IQR 仅 15.9（真值 IQR 839）
- p10~p90 挤在 31 分钟带内
- 分轴承 bias：Bearing1_4 +782.3，Bearing2_4 +664.2，Bearing3_4 +52.8
- 等价纯常数 842 的 RMSE = 490.37

**结论**：校准退化成常数，恰好对 Bearing3_4（真值均值 757）比较"顺"。

### 5.2 三道闸门设计

| 闸门 | 检测目标 | 阈值 | 理由 |
|------|---------|------|------|
| IQR 坍缩 | 预测分布是否坍缩 | ratio < 0.1 | IQR 远小于真值说明预测几乎不变 |
| 常数等价 | 是否等价于常数 | RMSE > 常数 RMSE × 0.95 | 允许 5% 误差，防止噪声误判 |
| 分轴承 bias | B 题最大 bias | max_abs_bias > 500 | 500 分钟是验证集 RMSE 的量级 |

### 5.3 闸门的有效性

| 场景 | IQR 闸门 | 常数闸门 | bias 闸门 | 结论 |
|------|---------|---------|----------|------|
| 保序校准 | ✅ 触发（ratio=0.019） | ❌ | ✅ 触发（bias=782） | 正确拒绝 |
| shrink a=0.45 | ❌（ratio=0.85） | ❌ | ❌（bias=427） | 正确通过 |
| 纯常数 | ✅ 触发（ratio=0） | ✅ 触发 | ✅ 触发 | 正确拒绝 |

## 6. 为什么选择收缩折叠技术？

### 6.1 问题发现

B 题需要"后处理收缩"（`p' = a*p + (1-a)*center`），但赛规要求检查点格式不变。

### 6.2 关键洞察

```
p = out * target_scale + target_mean
p' = a*p + (1-a)*center
   = a*(out * target_scale + target_mean) + (1-a)*center
   = out * (a*target_scale) + (a*target_mean + (1-a)*center)

=> 只需修改 target_scale 和 target_mean 两个标量！
```

### 6.3 优势

1. **零合规风险**：检查点格式不变，`model.py` 无需修改
2. **精确折叠**：误差 ~1e-13（浮点精度极限）
3. **可追溯**：`training.json` 记录 `shrink.a`、`shrink.center`、`shrink.folded_into`

### 6.4 对比方案

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| 后处理收缩 | 简单 | 需要修改 predict.py，合规风险 | ❌ |
| **收缩折叠** | 零风险 + 精确 | 需要数学推导 | ✅ |

## 7. 总结

本系统的设计选择遵循以下原则：

1. **诊断驱动**：每个策略都有明确的诊断依据，不是盲目尝试
2. **可解释性**：所有决策可追溯（诊断→策略→效果）
3. **合规优先**：收缩折叠、学习率下限等设计确保零合规风险
4. **方法论严谨**：LOBO 交叉验证、三道退化闸门、诚实口径（finalEpVal）
5. **可复现性**：所有超参数、随机种子、实验记录完整保存

这些设计选择使系统在三个工业任务上取得显著性能提升，同时满足赛规的全部合规要求。

# 演示材料（≤5 分钟视频拍摄脚本）

对应作品：Harness 自进化系统，镜像 `harness:1.0.0`，含 PyTRIO 大模型决策。

**核心原则**：画面里的每个数字都必须能和仓库日志对上。本脚本只使用当前镜像的真实实测值，宁可少拍几个角度，不出现任何编造数字。

---

## 0. 拍摄前准备（不录进视频）

```bash
# 1) Key 只进环境变量，画面里不得出现任何 Key 字符
export PYTRIO_API_KEY=<key>
export PYTRIO_MODEL=Qwen/Qwen3.5-4B
export HARNESS_BASELINES=/app/tasks/B/baselines

# 2) 干净输出目录
rm -rf demo-output

# 3) 终端：字号 ≥ 18pt，深色背景，关闭无关标签页
```

器材：屏幕录制（OBS / Win+G / Cmd+Shift+5），1920×1080，30fps。

## 2. 旁白全文（约 460 字，语速正常约 3 分 40 秒，留出训练等待）

> 各位评委好。我们提交的是工业模型自进化 Harness。它不换网络结构，只让系统自己决定怎么续训，并在每轮之后自己判断该不该上线。
>
> 闭环六步：漂移监测、诊断归因、策略选择、实验优化、退化检查、评估上线。第 3 步由 PyTRIO 的 Qwen3.5-4B 完成——它读基线代码、读诊断、读最近三轮历史，输出策略和超参，再由 Harness 校验执行。模型只能从候选策略里选，超参只能在允许区间内改，越界的值会被夹回边界。
>
> 现在跑 B 题三轮。
>
> 第 1 轮，监测显示没有主导轴承，最大 MSE 占比 44.5%，低于 80% 阈值。模型选择把预测向训练集中位数收缩，系数 0.3。RMSE 458.48，比官方基线 681.16 低 32.7%——数字很漂亮。但闸门拒绝了：预测的四分位距 67，真值 839，比值 0.080，分布已经塌到常数附近。
>
> 第 2 轮模型决定不改超参，RMSE 467.64，与可部署常数 470.86 统计等价，闸门第二次拒绝。第 3 轮它参考历史选了更大的收缩 0.6，RMSE 486.06，更差，回滚。三轮零上线，最后保留的是原始基线检查点。
>
> 这就是我们想说明的事：分数变好不等于模型变好。收缩能让 RMSE 好看，代价是模型不再给出有区分度的预测。
>
> A 题是唯一真正上线的。类平衡加权加高斯噪声增强，Macro-F1 从官方基线 0.7140 提到 0.7412，涨 3.8%。代价是其中一个类别的 F1 只有 0.05，这个改进不均匀，我们写进报告里了。C 题三条策略是 92.86、262.45、101.12，全部劣于常数 79.41，全部回滚。
>
> 每一轮的每一项判定都落在实验记录里，任何人可以复算。代码、日志和复现步骤都在仓库里。谢谢各位评委。

## 3. 拍摄注意

1. **绝不出现 API Key**。需要示意时只显示前 6 位。
2. **不要用加速播放掩盖回滚**。三轮全部回滚是这套系统最有说服力的部分，必须完整保留判定行。
3. **训练等待**：B 题单轮在 CPU 上是数十秒量级，三轮合计数分钟。机器慢就改成预跑日志回放，但字幕必须标"预跑日志回放，非现场运行"。
4. **只能出现的数字**（全部可查）：
   - B：458.48 / 467.64 / 486.06，基线 681.16，可部署常数 470.86，预言机常数 465.73，真值 IQR 839，预测 IQR 67.18 / 100.77 / 134.36
   - A：0.7412（基线 0.7140），Accuracy 0.8955
   - C：92.86 / 262.45 / 101.12，可部署常数 79.41，基线 52.87
   - **不要出现**：681.16→452.64、0.7519、50.54、NASA 5.823e9 / 3.448e9、448.72 / 443.42 / 475.16。这些是旧口径或模拟端点产物，已撤回。
5. **字幕**：关键行加固定字幕条（"第 3 步：PyTRIO 决策""退化闸门：IQR 坍缩""退化闸门：常数等价"）。

## 4. 答辩 Q&A（与视频口径一致）

**Q：大模型具体做了什么？**
> 在策略选择这一步，它拿到四样输入：本轮诊断、基线 `model.py` 的代码摘录（≤900 字符）、`configs/*.json`、最近 3 轮历史。输出一个 JSON：策略名、超参覆盖、理由、以及它从代码里读到的观察。Harness 按白名单和边界校验后执行，整条决策存进 `llm` 字段。

**Q：怎么证明真调用了模型？**
> `experiment_history.jsonl` 每轮有 `llm` 字段：`source`（`llm` 或 `heuristic`）、`model`、`endpoint`、`latency_s`、`usage`（prompt/completion token）、`finish_reason`、`reason`、`code_notes`。B 题三轮 `source` 全是 `llm`，延迟 1.2s / 0.84s / 1.89s，prompt 约 1285 token——这些数字伪造不了，因为网络断开时会自动变成 `heuristic`。

**Q：常数等价的判定标准？**
> 参照物是**可部署常数**：训练集标签中位数（B 题 758.5），在验证集上算得 RMSE 470.86。这个数部署时不需要验证集标签。模型 RMSE 必须低于它的 98% 才算真改进。验证集标签中位数算出的 465.73（预言机常数）只记录、不参与判定，因为那需要验证集标签，赛规不允许。

**Q：B 题三轮零上线，是不是系统不行？**
> 恰恰相反。第 1 轮 458.48 比官方基线好 32.7%，如果我们只盯分数就会上线它，交付一个几乎输出常数的模型；隐藏测试集上会立刻崩。闸门拦住它，是系统按设计工作。我们宁可交一份"零上线但可解释"的记录，也不交一份"分数好看但机制错误"的记录。

**Q：为什么 A 题能过、C 题过不了？**
> A 题的问题是协变量漂移（跨批次 LDA 准确率 0.4043 低于随机 0.4277），重加权加噪声正好对症，所以真涨了 3.8%。C 题的问题是策略池时间尺度错配：基线自己只训了 15 epoch，我们的策略一律续训 300 epoch，把 833 个参数的小网络带离了基线解，结果比基线差 1.7 到 5 倍。闸门拦住了，但策略本身需要重做，这条已写进报告的已知局限。

**Q：C 题为什么不继续调到达标？**
> 因为当前策略池里没有"零改动"和"小 epoch 续训"这两个安全选项，继续跑同样三条策略只会重复失败。我们选择把缺口写清楚，而不是临时改口径让它"通过"。
